# TransitFlow V2 — Master Product Specification
Status: agreed requirements, NOT evidence of implemented functionality.
Authority: this specification supersedes older V1 README where they conflict.
Do not change business decisions without documenting an explicit user decision.
Last consolidated: 2026-11-10.

## 1. Product and identities
Single Moroccan delivery company, not a multi-company SaaS. Merchants, warehouse, internal employees, departments/responsables, partner agencies per city (multiple per city), drivers, Admin, one unrestricted technical Developer. Exactly one shared login per partner agency; its audit identity is the agency. Separate developer technical dashboard for partner API credentials/mapping, logs, resync, templates, backups and 2FA. Admin and authorized managers grant per-module permissions. Retour permission enables normal Retour work across Bons/complaints but never bypasses locked Bon membership. Only Admin or specifically privileged Responsable Finance may confirm agency payment Paid. Agency data isolated even within same city; merchant data isolated.

## 2. Orders and scanning
External merchant-prepared orders and internal warehouse stock orders. Tracking e.g. BOXSH34789066. Ticket 100x100 mm with batch printing/reprinting; printing alone must not alter status. Typical statuses Attente de ramassage -> Ramassé -> Expédié -> Reçu par ville -> Mise en distribution -> Livré / Refusé / Annulé / Pas de réponse / 2ème appel / 3ème appel / Reporté. Exchange (Colis remplacer) delivers new parcel and collects old parcel under SAME tracking, marked exchange, original Livré and COD never duplicated. Order table columns Code Suivi, Destinataire, Téléphone, Ville, Statut, Marchand, Prix, Agence, Actions; sort by actual status change timestamp; filter merchant/city/status/agency/date. Export ALL filtered rows (not just page) with CODE SUIVI | DESTINATAIRE | TELEPHONE | ADRESSE | PRIX | VILLE | COMMENTAIRE | MARCHANDISE | QTY | PEUT OUVRIR | COLIS REMPLACER.

USB barcode reader and phone camera, online only. Green success + short sound; red duplicate + short sound; persistent unknown/wrong status/wrong agency error as appropriate. Nonblocking stacked toasts, last 20 scans per session plus permanent server history, counts reset on leaving. Server idempotency and concurrency control, retry after server errors. For manual typing/paste in scanner input, explicit responsibility confirmation and immutable log; never falsely attest a physical barcode scan based on keystroke heuristics.

## 3. Pickup and dispatch
Merchant pickup request; dispatcher assigns employee by zone; statuses En attente/Affecté/Picked/Reporté/Terminé/Annulé. Cancel only before Picked. Employee collects, warehouse closes after arrival.
Dispatch Bon selects city + agency, initially En préparation; eligible Ramassé orders from all merchants, scan/checkbox/Tout ajouter over filtered results and all pages, partial bulk success, search code/phone, pagination 50, 15-second refresh. Adding immediately marks Expédié and autosaves, removing reverts Ramassé, deleting Bon reverts. Multiple staff can collaborate; no duplicate additions. Envoyer changes Bon to Envoyé/En route, parcels remain Expédié. Reopen/edit/delete before agency receipt; locked after receipt. Per-agency Excel export templates.

## 4. Partner status and physical custody
Partner last-mile statuses synced via API; unknown statuses retained under Statuts non mappés, never silently dropped or notified. Mapping changes replay affected events chronologically, recompute unpaid financials but NEVER mutate Paid invoices. Out-of-order status corrections require reason, actor/source audit. Manual bulk Reçu par ville/Mise en distribution allowed. Partner outages preserve last-known status and alert team.
Order status and physical custody (Dernier Scan / Détenteur actuel) are INDEPENDENT. One current holder per parcel. Excel upload alone NEVER changes custody. Receiving return scan moves holder from agency to main warehouse; agency Stock Colis excludes it immediately, while historical status remains visible. Partner portal cannot edit TransitFlow order statuses.

## 5. Stock
Per-merchant isolated stock. Stock order requires all items available; otherwise Manque de stock and NO ticket. FIFO reservations distinct from physical; physical deduction ONCE at Ramassé scan or bulk after print. Oldest shortages reconsidered first on replenishment. Adjustments may invalidate reservations. Returned stock parcel restocks exactly once after actual Retour receipt, with damaged goods handled separately; external parcel goes to merchant Retour Client queue. Packaging charges Sachet Petit/Grand, Carton Petit/Grand only if company-packed, per-merchant fees, bulk setting with audit. Heavy-item overrides require actor audit.

## 6. Retour Agence: Bon creation and membership
Partner agency has one portal: Stock Colis based on last physical holder (counts Refusé, Annulé, 3 jours sans réponse, En voyage etc), search/filter and Excel export Code Suivi, Statut, Dernier Scan, Date, Agence; its own Bons, Attendus/Reçus/Manquants and PDF. No separate Colis reçus aujourd'hui widget. Per-agency Excel mappings configured by Admin.
Uploading Excel immediately creates Bon (no preview), deduplicates codes inside same file; invalid known statuses appear Commandes sans état valide, unknown codes in Anomalies with reason. Same content/file repeated while original active => prevent and link original; if Bon deleted before any scan, identical file may create a new Bon. Different Excel can include codes already in other Bons; do NOT reject solely for overlap.
Agency-created Bon: ONLY agency can add/remove codes until first successful scan; staff cannot edit its list. Staff-created Bon: agency sees it immediately but cannot edit/delete; authorized Retour staff can edit/delete before first scan, with confirmation for deletion. Agency additions before lock need no confirmation, removals require confirmation; deleting unscanned agency Bon requires confirmation. After FIRST successful scan, NO ONE (even Admin/Developer) may add/remove membership. System-driven outstanding reconciliation is allowed without altering membership: receipt in Bon A removes the same code from Attendus in other open Bons, with audit reference to A; closed Bons unchanged. Before first scan edits autosave; other sessions use manual Actualiser. Scan always checks current DB; removed code rejected with Code retiré du Bon — Veuillez actualiser. No implicit Retour non déclaré within a Bon.

## 7. Retour Agence: receipt and closure
Only accepted codes on Bon, status Refusé or authorized return, and currently held by correct agency may be received. Mise en distribution etc rejected with Voir commande new tab; authorized employee may correct status with mandatory Motif then rescan without refresh. Wrong agency shows correct one; duplicate/unknown rejected. Livré rejected except Retour Échange: original delivered state and COD unchanged, old parcel goes Retour Client. Optional Colis endommagé flag/photo/note, merchant sees and PDF prints ENDOMMAGÉ, audited.
Scanner accepts USB/camera and manually typed/pasted tracking code in same input. Manual entry must warn: Vous confirmez la réception de ce colis sans scan physique. Cette opération sera enregistrée sous votre responsabilité. Record exact employee, method, time, agency and Bon, distinguishing manual assertion from verified scan. All accepted codes must be received to close Bon as Reçu; manual receipt is allowed but separately marked unverified physically. Bon Brouillon -> Envoyé -> Reçu final, may reopen Envoyé to Brouillon before Reçu, but membership still locked after first scan. Sessions autosave, multiple staff. Reçu irreversible with confirmation and counts. PDF after Reçu ONLY actually received parcels, A4 repeated headers, page x/y, Bon ID/agency/date/count/codes, no signature/stamp. Bon filters agency/date/status, search ID/code, pagination.

## 8. Retour Client
External returned parcels queue per merchant after physical receipt; merchants sorted by pending count descending. Multiple merchant-specific Bons per day. Search code/phone, filter actual receipt date, Tout ajouter applies to filtered rows across all pages, dedupe repeated batches. Concurrent staff server-validated and audited, optional verification scan but NOT required for send. Bon PDF includes all included parcels regardless verification, exchange/damaged labels, merchant/date/number/count/signature, two print copies, updated PDF only, revision audit. Status En préparation -> Expédié vers client (Retour staff may reopen without reason) -> Reçu par client (staff marks, locks, merchant notified) -> En attente de confirmation marchand -> Confirmé par marchand (merchant confirms EACH Bon, no timeout/auto-confirm). Admin exceptional Reçu par client -> Expédié vers client only before confirmation, mandatory reason and audit, invalidates pending notification. Manual prefilled WhatsApp link, no WhatsApp API. Merchant may complain after confirmation; no employee notification for confirmation.

## 9. Finance
Livré via API immediately credits merchant available COD net of merchant-specific city delivery fee and charges, INDEPENDENT of partner remittance. Merchant-specific refused fee default 0; returned fee 0; debts offset future. Merchant payout invoice created by Admin from selected eligible delivered parcels, visible to merchant, paid by cash/virement, immutable after Paid; corrections use adjustments. Monetary values in integer centimes and idempotent ledger.
Separate manually created Bon de Paiement Agence (like dispatch Bon), authorized employee selects agency and eligible Livré parcels not already in another agency payment Bon; date filter often last 24h, Tout ajouter, totals. Each parcel at most one agency payment Bon. Partial remittance, e.g. 15000 of 20000 MAD, stays En cours de traitement and shows 5000 outstanding. Only Admin or specifically permissioned Responsable Finance may confirm Payé once fully received; audit confirmer/time/amount.

## 10. Réclamations
Merchant can complain about order/pickup/stock/invoice/settlement/return/other; linked reference, immutable chat/attachments, private staff notes. One active complaint per merchant/reference; merchant may cancel anytime; reopen closed up to 3 times then new. Status Ouverte/En cours/Résolue/Fermée/Escaladée/Annulée. Staff may close without reason; merchant notified. Admin urgency. Escalated director-only until delegated. General assignment by merchant/least workload/round robin; manager presence Présente/TT/Absente, absence blocks login and redistributes; performance visible only managers. SLA Mon-Sat 9-12 and 14-18 Morocco holidays, 1 working hour no staff reply red, 2 hours manager notice, reassignment does not reset.
Retour-specific complaints: <=10 active Retour complaints, self-claim; >10 auto-balance ALL across available Retour staff including previously assigned; below threshold no forced reassignment. Absence/permission revocation reassign to Retour; if none fallback general support; return to Retour when staff available. Any Retour staff can reply/close without changing assigned owner, audit author. New merchant messages grouped alert to ALL available Retour staff; any reply clears group for team. Real-time chat sorted latest; complaint can be filed after confirmation, optionally affected parcels, no per-parcel Signaler un problème button.

## 11. Notifications, security and operations
Single anti-spam bell, unread first/read lower, Tout marquer comme lu, grouped alerts, no notification per scan/order status; role-specific, audit and persistent history. Clicking marks read, not resolved. Light toasts, no sound except critical and scanner.
Server-side deny-by-default permission and resource scoping, agency/merchant isolation even by guessed IDs, MFA Admin/Finance Responsable/Developer, secure sessions and revocation, encrypted partner API secrets, input and Excel validation, rate limiting, audit and idempotency. Daily encrypted backups retain 30 daily and 12 monthly with restoration tests. Developer technical logs/manual resync; minimize PII in logs.
Performance goals are targets, not claims: p95 scan <=300ms, simple API <=200ms, dashboard <=2s, load test >=100 concurrent staff; race tests for scans, Bon locking, stock and COD.
